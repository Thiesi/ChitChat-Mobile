# Test-only framework input-method control

This diagnostic component lives entirely in `app/src/androidTest`. It adds no product feature, keyboard workaround or release waiver. The production manifest and APK must contain no diagnostic service. Normal full CI uses its stock keyboard and every existing test/assertion. This independently scoped branch retains main's172 tests and adds four inert isolation checks (expected176); the earlier stacked199-test checkpoint is separate evidence.

## Implementation and isolation

`DiagnosticImeService` requires Android's signature `BIND_INPUT_METHOD` permission and runs in the test package's separate `:diagnosticIme` process. Its native200dp panel has Space/Delete buttons that write only on explicit clicks. It never reads surrounding/editor text, retains EditorInfo/connections, accesses the network, requests focus/IME visibility, schedules timers or repairs input. Super callbacks delegate normally. No source/CI automatically enables or selects it.

The service and event helpers depend only on Android/Java platform types and the test APK's generated resources. AGP removes target-provided Kotlin dependencies from the test APK; ordinary instrumentation can conceal that because it includes the application classpath. An isolated test-APK `PathClassLoader` regression originally failed on `kotlin.jvm.internal.FunctionReferenceImpl`; replacing the diagnostic service/helpers with platform-only Java made the unchanged regression pass. Application code remains Kotlin/Compose. This fixes a diagnostic-fixture packaging defect, not the original chat input failure. No service-crash capture establishes it as the sole cause of the original minimal-IME no-focus result.

Four inert tests verify the protected declaration/process, production absence, scalar log budget, and standalone helper initialization/service ABI loading without the target APK. They do not select the keyboard. The `ChitChatTestIme` tag emits only `n=<ordinal> t=<uptime> e=<fixed enum>`: at most1024 callbacks plus one LIMIT marker per service instance. No text, editor identity, connection, exception or raw fallback is logged. A cap/restart/capture gap means missing evidence, never an absent event. Normal CI does not opt into this tag.

No warmup, tracing/round override, tap replay, focus/show repair or readiness gate. Both arms are predeclared; native failure alone does not cancel the other. Setup/source/identity/timeout/capture-integrity failures abort remaining work. Preserve every negative. ADB0 alone is not native success.

Collectors accept only the existing scalar allowlist plus the exact bounded callback grammar for this separate experiment. Alternate-IME success cannot replace stock/full failures or establish sole keyboard causation.
