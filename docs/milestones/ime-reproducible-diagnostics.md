## Scope and boundaries

- Normal full CI still invokes the ordinary unfiltered, untraced native gate exactly once. A suite-level setup enlarges the logcat ring to16MiB and clears it once. Failure capture keeps at most2,000 allowlisted lifecycle records and preserves the original Gradle status even if capture fails. `onProgress`, fixed API36 `PHASE_*` values and all fixed `SoftInputShowHideReason` values come from immutable AOSP android-16.0.0_r1 sources; unknown names and arbitrary content stay excluded.
- Under the [technical lead's retention decision](https://github.com/Thiesi/ChitChat-Mobile/issues/69#issuecomment-6715949478), observed failed-test windows take priority: start through failure/cleanup and finished marker. When over the cap, discard oldest outside-window progress records first, then oldest other outside records. Retained output stays chronological. If failed windows alone exceed2,000, keep their newest records under the same cap. Missing starts are unknown (priority begins at the failure marker); missing ends retain the available segment until the next start or stream end. Without an observed failure marker, the original newest2,000-record policy remains. Nothing recovers data already overwritten in the device ring.
- Failure-only `input_method` capture scans the complete available stream with4KiB reads and a64-character boundary carry, under a2-second elapsed bound and dumpsys service timeout. It retains at most40 existing fixed flags, with independent timestamps and an incomplete/flag-cap indicator. It never retains raw lines or dumps. The separate IME-window collector keeps its65,536-character bound. Timeout/unsupported metadata is unknown, not hidden-state proof. No collector runs before a tap or repairs focus/IME.
- The Linux journey environment pins emulator build16740729 (37.2.13.0) and API36 Google APIs x86_64 image revision7. The action's sdkmanager install validates its package archive; a pre-launch hook checks that revision and the actual emulator build. If a newer image was installed, the hook replaces only that SDK image with Google's fixed revision7 archive after size/checksum/CRC/revision checks. Archive metadata comes from Google's official repository index (1,895,447,397 bytes, SHA1c6bf44bdcd885bb902b4ba752d111a073ad7a817). Temporary downloads are removed immediately. Cores/RAM, spell checker and autofill configuration are unchanged.
- One environment report before instrumentation records only IME component/enabled list/version, image fingerprint/security patch/revision, emulator version/build, hardware-keyboard preference/configuration qualifiers, animation values, spell-checker settings and autofill component. Missing facts remain null. One fail-fast check requires the pinned revision7 image's actual Gboard/LatinIME component enabled/selected, software keyboard preference1 and all animations0. It also rechecks the image and emulator pins, because the action may continue after a failed pre-launch hook. Version probes are headless. A failed check starts no instrumentation and never retries. It is neither per-tap readiness nor proof the IME pipeline will succeed.
- Only `CompletionJourney.cleanup` and `SearchResultJourney.hideIme` change existing sampling: their same5,000ms wait requires Compose inset0 **and** native `imeVisible=false` together, keeping the final assertion. This is the explicitly approved cleanup-only change, with no deadline extension, extra tap or relaxed predicate. Successful input paths are unchanged.
