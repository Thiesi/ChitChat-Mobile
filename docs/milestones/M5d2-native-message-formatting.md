# M5d2: native message formatting and explicit links

Room and DM bodies consume [M5d1's bounded parser](M5d1-message-format-parser.md): strong/emphasis, inline code, quotes, wrapped fenced code and HTTP(S) link styling. Tapping or long-pressing the existing48dp message body opens its actions; link choices there have explicit48dp targets and show the normalized destination before opening another app. The disclosure explains that handoff. There is no automatic URL request, preview, HTML rendering or general Markdown expansion.

## Content and scope

Room emotes keep the literal `* username ` prefix and parse only their body inline, matching the pinned browser [room renderer](https://github.com/Thiesi/ChitChat/blob/4f53ff497f5572072fddad42d8ac3979e9cdf0d1/public/assets/js/app.js). Ordinary room and [DM bodies](https://github.com/Thiesi/ChitChat/blob/4f53ff497f5572072fddad42d8ac3979e9cdf0d1/public/assets/js/messages.js) use block parsing. Code and rejected URL candidates stay inert. The16,384-unit URL limit also covers normalized addresses, so Unicode expansion cannot create a choice that export would reject. Mentions remain text without invented authorization/highlighting/completion. Reply excerpts, drafts, sends, author editors and whole-body Copy keep their original literal source and canonical rules. Duplicate normalized link destinations get one explicit choice.

The component remembers only ephemeral presentation data within its existing composition, never saved state, a global content cache or disk. Existing deleted/ignored-row branches still own redaction. Link callbacks freeze the rendered session/room/peer, original modal reference and canonical row, then repeat `canUseMessage` before export. Each link button is keyed by normalized destination: changing a URL retires its pointer/semantics node instead of replacing the handler beneath a pending press. A queued callback cannot export an edited/replaced/retired owner's URL. The actions modal continues suppressing native read/typing proof while the external Activity takes over. A failed launch leaves explicit Copy/Close available and shows a generic error with no URL/error logging.

The exported intent has only `ACTION_VIEW`, the validated HTTP(S) address and `CATEGORY_BROWSABLE`; it carries no session transport, cookies, CSRF, auth extras or clipboard payload. Notification destinations retain their separate guarded native routing; this is only an explicit message-link export. Existing session cookies in another app are outside this client's transport. No browser fallback is added to unsupported notification targets.
