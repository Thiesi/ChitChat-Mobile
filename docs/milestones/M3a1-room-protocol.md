# M3a1: room protocol prerequisite

This independently buildable prerequisite is split from the native M3a room directory to keep both complete diffs within the Claude review-input budget. It adds no fake UI, realtime connection or alternate authentication system. The native consumer follows in a dependent PR.

`RoomOperations`/`SessionRoomRepository` use the existing generation-bound session capability and TLS/cookie/CSRF transport for actual `rooms/list.php`, `detail.php?room_id=…`, `join.php`, `leave.php`, and `create.php` contracts. List/detail/join/leave require200; creation requires201 and the current account as immutable owner. Typed schema, ID/duplicate/membership/policy validation, exact request payloads and safe status/error handling are tested. No automatic POST replay or response logging exists. Resource403 remains local;401 retires the session; CSRF failure requires refresh. The capability fence discards late private room data after logout.

Shared creation validation matches backend key normalization, PHP trimming, Unicode code-point limits, visibility/minimum-age/inactivity rules and guest scope. Only non-guest super_admin/admin/chat_admin gets create affordances; server authorization remains final. Wire models have no generated content strings or disk cache. Backend source remains unchanged at the audited v3.2.1 /4f53ff4 baseline. Source evidence: `docs/api/rooms.md`, `src/Room/{RoomService,RoomRepository,RoomAuthorization,RoomKey,Room}.php` and the five existing endpoints. No backend issue or speculative route is necessary.

The dependent consumer's units, live case and emulator suite are not substituted for this isolated gate. No isolated live config is created/copied; normal/hosted tests use fixtures only. Native discovery/membership/creation presentation, cancellation/reconciliation/draft handling and UI acceptance belong to M3a's consumer PR.
