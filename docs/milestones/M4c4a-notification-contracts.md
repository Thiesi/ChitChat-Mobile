# M4c4a: notification HTTP and native-route contracts

This is an independently buildable protocol prerequisite, not a native notification center or push integration. It consumes existing v3.2.1 endpoints through the original session transport. No backend source/history/configuration changes, invented event/field/endpoint, browser wrapper or parallel authentication were introduced. Native read controls, unread badge, target windows/navigation and guest consumption follow separately.

## Authoritative contracts

[`list.php`](https://github.com/Thiesi/ChitChat/blob/4f53ff497f5572072fddad42d8ac3979e9cdf0d1/public/api/v1/account/notifications/list.php) accepts positive exclusive `before_id` and `limit1..100` (server default50). [`PrivacyNotificationService::timeline`](https://github.com/Thiesi/ChitChat/blob/4f53ff497f5572072fddad42d8ac3979e9cdf0d1/src/Account/PrivacyNotificationService.php#L49) returns newest-first rows plus an independent `unread_count`. Models preserve `id,kind,title,message,details,link,read,read_at,created_at`; unknown kinds are accepted, not mapped to a fabricated enum/category. Validate strict ID-DESC uniqueness/bounds, timestamps, actual Boolean/read-at consistency and nonnegative counts. Local older cursor is the raw last ID; a full page only means another page may exist. Empty/short pages do not invent server snapshot guarantees.

[`read.php`](https://github.com/Thiesi/ChitChat/blob/4f53ff497f5572072fddad42d8ac3979e9cdf0d1/public/api/v1/account/notifications/read.php) requires the existing CSRF header. Send integer `ids` (at most100; empty/duplicate IDs valid) or a literal JSON `{all:true}`. Server ownership filtering/monotonic reads mean `updated:0` is valid. All includes unloaded/newly arrived notices at operation time, not just loaded rows. `updated` cannot exceed distinct requested IDs for an ID batch; global unread count can differ from visible rows. No request or returned count marks room/DM history read.

## Scope, errors and privacy

`SessionNotificationRepository` uses `openAccess(expected)` and `authorized(originalCapability)` for every request. The caller must supply its rendered original SessionState; it cannot silently acquire a replacement user's capability. Copy ID selections before waiting for access. Session retirement cancels in-flight TLS/HTTP; late results cannot publish after logout. Common bounded1MiB JSON, HTTPS verification, cookie origin/path restrictions, CSRF and typed401/403/429/503/transport errors stay in the existing layer. No independent jar, permanent background connection, guessed notice SSE event or implicit POST replay is added.

These models have no generated private-text string representation and no persistence/UI consumer. A future native state model must retain ambiguous write state and offer explicit GET/session reconciliation rather than retrying All or fabricating success. Actual Boolean deserialization is shared with typing through a neutral `StrictJsonBoolean`; missing/null typing preference remains unknown, not opt-in.

Rendered notices can include usernames and mute reasons. Introductory backend privacy prose does not fully match its actual renderer; do not repeat a blanket absence/safe-lock-screen promise. Text/details/links remain private, untrusted plain text, never HTML, credentials or log content. The server does not include raw chat bodies here. Push public-version privacy is still M6, not inferred from this transport.

## Native destinations are hints, not completed navigation

The parser recognizes service-generated room/message/ping and restored-room URLs, numeric `user_id` DM URLs, account, and future guest-registration links. Ignore `peer_name` as an identity hint; use numeric peer ID and later server authorization. The current browser's separate `with` parameter is not assumed to be the service's notification contract. Only selected-origin HTTPS/root-relative links with exact recognized raw paths/query keys are supported. Reject credentials, foreign ports/origins, network paths, raw controls/backslashes, fragments, normalization/traversal tricks, duplicate decoded keys, mixed message/ping targets and malformed/overflow/nonpositive ASCII IDs. Unknown links leave notice text intact and never become arbitrary browser/API intents. Representing Registration does not implement guest migration or authorize account changes.

Discovery corrected an unnecessary traversal assumption: [room history](https://github.com/Thiesi/ChitChat/blob/4f53ff497f5572072fddad42d8ac3979e9cdf0d1/src/Room/MessageService.php#L52) and [DM history](https://github.com/Thiesi/ChitChat/blob/4f53ff497f5572072fddad42d8ac3979e9cdf0d1/src/DirectMessage/DirectMessageService.php#L173) accept arbitrary positive exclusive-before IDs. A target+1 bound fetches the retained/authorized target plus older context in one existing bounded page; omit the bound at maximum signed ID. Future native consumers must verify the exact returned ID, keep fixed historical bounds/no unseen latest reads, hydrate existing mutation/file metadata and handle missing/deleted/unauthorized targets explicitly. No around endpoint or newest fallback is invented. Ping targets remain limited to the existing latest100 records.
