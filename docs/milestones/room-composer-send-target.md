# Pinned room composer and compact controls

This independently buildable prerequisite addresses a real room-layout weakness found during PR29 verification: Send shared a vertically scrolling column with the multiline field, status and reentry controls. A keyboard-visible short viewport could require scrolling between input and action. The existing issue24 fixture also intermittently reported zero send calls; its exact tap/IME mechanism remains unproved. Original failure evidence is retained under ignored `.tooling/m4b-post-orientation-room-zero-send-failure` and recorded on [issue24](https://github.com/Thiesi/ChitChat-Mobile/issues/24). This is not a transport or backend fix.

`MessageInput` is one Material-decorated native multiline field through compact/expanded layout changes. Keep it beside a pinned, minimum-touch-target Send button outside any composer/status scroller. The field's internal text scrolling cannot move Send. Drafts remain ViewModel-only; no automatic send, POST retry, content persistence or new dependency. The dependent DM consumer can reuse this component instead of maintaining a duplicate.

Room status, mute/member/guest restrictions, presence/reentry, unknown-send reconciliation/consent, refresh, private pings and cancellation remain in the normal scrollable header and an always-adjacent, badged Room details action. Constrained height hides the header, not those controls. Blocked-send attention explains where to find the reason/recovery. Opening private pings dismisses details first. No authorization, presence activity or chat-transport semantics change; existing PHP session/CSRF APIs only.

Initial PR30 review found three worthwhile improvements: remove an editable field's overriding content description, make blocked-send recovery reachable beside input in normal layout too, and declare the software-keyboard test precondition. Native semantics now verify exposed EditableText/no overriding description ([Android content-label guidance](https://support.google.com/accessibility/android/answer/7158690)); manual TalkBack remains pending. Room details is always adjacent, with blocked-send attention, and a normal-layout unknown-send/consent regression. Hardware-keyboard runs need no IME; CI explicitly enables it and passes `expectSoftKeyboard=true` for strict inset readiness. A later70-case repeat had one zero-reentry fixture action, preserved under `.tooling/room-composer-70-reentry-zero-call-failure`; it now uses adjacent details/explicit Enter and waits for the selection-request count. The separate ACTIVE acknowledgment is still required before send/read; no click retry.

Read proof requires RESUMED lifecycle, window focus, unobscured live edge and a visible newest-row bottom, not an entire tall-row fit. Details/private-ping overlays cannot acknowledge content behind them. Explicit retry controls use latest-window availability, not the temporarily false obscured `atLatest` proof; closing the dialog and the ordinary viewport gate still determine whether a POST is eligible. No uncertain-read hot loop or synthetic acknowledgment.

The next review correctly caught that placeholder-only naming disappears with a nonempty draft. The field now uses Material's persistent label slot and merges that label alongside EditableText, without a content-description override or an invented hint API. Native send assertions verify the label and exact multiline draft together. The compact composer reserves64dp for the floating label. The revised focused18 and actual-landscape/font150% six-case runs passed; an independently installed fake tall-send case also passed and its keyboard-visible screenshot was inspected (`.tooling/room-composer-persistent-label-landscape.png`). Manual TalkBack is still unperformed.
