# M2b2a: sensitive-action protocol and session foundation

This is the independently buildable protocol prerequisite for M2b2, split so the reviewer receives the entire diff within its126KB input gate. Existing native registration/authentication UI is unchanged here; no usable export/step-up UI or live export is claimed. The following native UI/export PR supplies the actual consumer and its own evidence. Android main was fetched/current at `9a6f33e`; backend remains read-only v3.2.1 / `4f53ff4`.

The existing session client now has typed calls for authenticated MFA/password metadata, password step-up, emergency recovery step-up, and personal export. Envelopes/status/method/lifetime/account/format are validated against the actual backend. `SessionAccess` binds the same TLS/cookie/CSRF transport to a generation/account/version, checks lifetime/cooldown below UI, persists validated cookies and rejects stale callbacks. Resource403/malformed payloads do not become global logout;401 invalidates and CSRF/network ambiguity requires explicit refresh. Confirmed recovery counts update shared session state.

The PR #9 timestamp compatibility fix parses the backend's PHP `DATE_ATOM` offsets with `OffsetDateTime.parse(...).toInstant()`, available from [API26](https://developer.android.com/reference/java/time/OffsetDateTime#parse(java.lang.CharSequence)). Older [Android libcore instant parsing](https://android.googlesource.com/platform/libcore/+/0dac6dd2e30993ba45f77a20982928dae33200c8/ojluni/src/main/java/java/time/format/DateTimeFormatterBuilder.java) expects a literal `Z`, so passing JDK17 fixtures alone did not establish support for `+00:00` on the minimum Android runtime. The shared validator retains active/method/lifetime checks and fail-closed malformed/null timestamp handling. Unit fixtures exercise both `Z` and `+00:00` through password and recovery responses; three added Android regression tests use the production validator directly.

`withStepUp` permits one action retry only for403/step_up_required after explicit successful verification; a second rejection or ambiguous failure never loops. There is no auto-recovery/password replay. Export uses a bounded16MiB/120-second path in the existing executor, not a second HTTP/session architecture. Other JSON retains1MiB/25seconds; oversize export is an explicit resource error. Secret-bearing wire/access/export models have no generated content string representation and no disk/log output. Native passkey/provider flows remain B1/B2 dependencies, not assumed APIs.

Backend evidence: `public/api/v1/step-up.php`, `mfa/step-up-recovery.php`, `account/mfa/status.php`, `account/identities/list.php`, `account/export.php`; `src/Auth/SessionManager.php`, `PrivilegedStepUpService.php`, `MfaService.php`; `src/Account/PersonalDataExportService.php`; and `public/assets/js/step-up.js`.
