## Explicit intent and scope

Only the actual current root navigation/lifecycle may call open(original SessionState, navigationEntryId). The future root must fence its actual navigation-entry reference before opening; a restored route or stale root effect is not authority. A same-owner/same-entry configuration rebind keeps the original entry/query/pending work. Every rendered edit/Search/Next/Previous callback retains the exact MessageSearchEntry reference. Attempt, result, selection and failed-retry callbacks additionally keep their original object references; old Cancel/Retry/close callbacks cannot affect successors.

Owner identity includes server/account/local generation/session version and authenticated non-guest phase. Owner retirement, genuine background, navigation close and ViewModel disposal clear private query/results/selections and cancel pending work. Background retains only the root entry reference; reopening it performs no POST and restores no query/body. Root must skip genuine-background cleanup for configuration recreation. No SavedStateHandle, bundle, disk, log, SSE invalidation, timer, automatic foreground search or queued retry is introduced.

Queries have an explicit4096 UTF-16-unit memory guard: over-limit edits are rejected with inputTooLong=true, retaining the previous input without truncating or silently submitting it. Blank Search does nothing. This is not a substitute for the server's2..200 normalized Unicode/syntax validation. Request construction freezes the original raw query/scope/session before awaiting; edits during a pending search remain an unsubmitted draft and do not change that attempt.

## Bounded pages and errors

Retain one current25-row page, with the prior page visible while a new explicit request is pending. Next/Previous always use the completed page's query/scope and exact raw offset; they never combine an edited draft with an old offset. Previous moves back by the fixed page size; Next preserves the server continuation and stops at its5000 request ceiling. Results can move between independent offset requests; no stable history cursor, bulk export, accumulated cache, silent oldest-row eviction or canonical message window is invented. A future UI must label the completed query separately from any edited input and explain a bounded continuation even when hasMore remains true.

Network/validation errors retain the prior completed page and bind any explicit Retry to its failed attempt. Query/scope edits retire that retry choice, including edits/rejected oversized input while an attempt is still pending: a later failure cannot recreate its old-input retry. An input revision is captured before awaiting; unchanged-value callbacks do not count as edits. Incompatible/expired/scoped denial clears old results. Cancellation remains cancellation and never publishes success; any current-operation cancellation exposes revalidation rather than automatically replaying the rate-limited POST. Busy/revalidation/storage/shared cooldown rejects an action immediately, without a pending search that later runs on a session emission. Every successful reply and cleanup is fenced by owner/entry/attempt/sequence.

## Selection is only a hint

Select accepts the actual row object from the current result reference. It supplies a typed room-message or direct-message ID/target for the existing fresh GET-only target actor. It does not fetch, adopt canonical content, infer membership, mark chat/notifications read, grant uncertain-send consent or emit typing. Future UI must preserve the server's current DM non-E2EE/retention/inspection disclosures before showing DM excerpts and render excerpts as plain Text.

A busy/rejecting native consumer keeps the original selection. Successful atomic handoff clears only that same selection, preserving any successor created in its callback. Native adoption must independently verify root lifecycle/actual entry, original selection and target request/result, current owner/policy and room/DM write/draft guards. Fresh lookup can deny a search hint; never fall back to latest history or a browser.
