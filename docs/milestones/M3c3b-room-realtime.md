# M3c3b: canonical room/directory realtime and active presence

Buildable consumer of PR20's [canonical-history reader](M3c3a-canonical-history.md), continuing PR19's single process-owned foreground SSE runtime. Uses only the pinned existing ChitChat v3.2.1 HTTP/SSE/presence contracts. No backend checkout changes, guessed endpoints, independent session jar, background connection service, persistent message cache or push delivery were added.

## User behavior and consistency

- Actual native room/directory screens consume generation-scoped event invalidations while STARTED and reconcile on every new collector scope. A buffered hint is never treated as an applied transcript. Reconnect/foreground/periodic coordinator revisions re-read canonical HTTP; normal finite-stream closure alone does not repeatedly replace the timeline. Offline/error marks loaded state stale. Unrelated-room messages update directory counts, not the open transcript.
- Room-message/edit/delete/private-ping/reaction hints trigger fresh context/history/mutation/quote/attachment/ping reads. Event payloads never become displayed rows or personalized reaction flags, event IDs never become message/read IDs. Pending revisions coalesce behind user writes/GETs and drain afterward; failures wait for a new hint or deliberate retry rather than hot-looping. Automatic GETs never cancel/replay send/read/membership POSTs.
- Canonical adoption requires the bounded reader's lower-bound coverage. Keep at most500 messages/100 private pings in generation-scoped memory. Away from the edge, keep the captured raw boundary, newest bound and current viewport anchor/offset even if the user scrolls during HTTP. If a latest extension no longer overlaps within the bound, refresh the fixed old range and offer New messages/Jump latest. Incomplete coverage stays visibly stale with recovery, never stitches cached rows or skips an unvisited raw gap. Retention removes stale rows and selects a neighbouring anchor with an explanation.
- Refresh/Jump latest is still explicit for resetting a bounded range and for unknown-send reconciliation. Automatic sync preserves the unsent draft, unknown-delivery/duplicate-risk consent, initial unread divider, read cursor/attempt/error and private pings. Acknowledged own sends deduplicate by ID, preserve raw cursors unless memory trimming truly changes the lower boundary, and report activity only for the current room/account. Definitive permission loss clears inaccessible content; a concurrently uncertain send retains its unknown-delivery warning. CSRF/network/rate errors do not erase the transcript.
- Read acknowledgment still requires an actually visible newest message at the foreground live edge, fresh authorized context and acknowledged active presence. Directory reads, event receipt, background reconciliation, inactive/expired presence and keyboard-obscured messages do not acknowledge reads. Read requests have a separate sequence/fence, survive automatic GETs, and check identity before I/O as well as after completion. Session capability acquisition also binds the identity captured before waiting for the vault/state lock; normal same-identity CSRF refresh remains possible, replacement generations/versions do not.

## Presence and Android interaction

Membership and active presence remain distinct. A real room-directory tap requests entry only after fresh context confirms membership or the existing four global roles. Route restoration/resume alone does not acquire a lease or fake deliberate activity. An inactive/expired room offers Enter room; until the server acknowledges a lease, send/read remain disabled while the draft/history stay available. Existing membership/guest-write/mute checks still apply to sending.

The native header shows active/entering/inactive/expired/error status, server warning/countdown and explicit Stay in room. Its timestamp comes from the coordinator's heartbeat receipt and survives configuration recreation. Aggregate People online lists people (not connection count), labels guests, and hides stale/private users when the lease/list becomes unavailable. The coordinator retains serialized20-second renewal, false passive activity, genuine-background/offline inactivity and explicit reentry policy. Typing/scrolling does not reset inactivity. Acknowledged sends/pings and explicit Stay/Enter do.

The existing IME-aware, multiline, bounded-scroll header/composer/timeline layout is retained. System theme and accessibility semantics remain native; status is textual and warnings use polite live regions. No device/TalkBack/manual usability claim follows merely from fixture success. Guests remain an unimplemented visitation workflow, not silently enabled by presence rendering.

New cases cover invalidations during send/read/membership, own-event/ack convergence, raw omitted boundaries, older500-row ranges/late scroll/retention, nonoverlap/incomplete gaps, unknown-send consent/read errors/divider, permission races, actual identity changes ahead of observers, explicit acknowledged reentry and failure coalescing. Production behavior and read eligibility were unchanged; original failure XML is preserved. All four then passed in32s. They use local test operations, not live account requests or production fakes.

Full native, large-font landscape, final debug/JVM/lint/shrunk unsigned-release/test-APK and exact-head hosted/review gates are recorded when complete.
