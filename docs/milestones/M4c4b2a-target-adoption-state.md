# M4c4b2a: historical bounds, scoped callbacks and target-adoption state

This independently buildable correction/precondition fixes two existing user-facing risks and prepares normal room/DM panes to accept [M4c4b1](M4c4b1-message-target-state.md) exact-target snapshots. It is not a new native quote screen, notification center, search or push implementation. The combined state/native-quote working diff exceeded the existing complete-review input budget, so state/security and native controls have separate complete gates/reviews. The native worktree is preserved and follows without a routine confirmation pause.

## Corrections used by existing native screens

Room history retains an explicit fixed upper bound after older pagination or a historical window becomes empty through retention. Foreground, canonical hints and ordinary refresh keep that historical range rather than widening an empty range to latest. Explicit Jump latest remains available. A deliberate latest-history check for unknown delivery retains its existing explicit duplicate-risk flow; automatic reconciliation never supplies consent or replays a POST. Raw cursors, anchors, drafts, private pings, read cursors and room-only ignore semantics are preserved.

Room Send and DM input/send/block/entry callbacks bind the original rendered SessionState and room/peer, not a delegated live Flow value or whichever pane happens to be selected when a queued callback executes. New typed overloads reject old-account/old-pane calls before editing or networking; typing input follows only an accepted scoped edit. Explicit entry with the actual current account can establish its correct owner before a collector runs, without accepting a stale predecessor. No new authorization is invented: the existing server still authorizes every request.

## Adoption and denial integration points

`MessageTargetViewModel.adopt(request, accept)` performs the existing current-scope/current-policy/exact-available validation and consumes only after the caller accepts. A busy consumer retains its selection; a callback that replaces the selection cannot have its successor cleared. Existing `consume` delegates to the same logic.

Both conversation VMs expose same-room/peer adoption, not arbitrary cross-conversation navigation. Rebind current policy, reject active message/read/block writes without cancelling/replaying them, replace only with an exact authorized historical page, preserve drafts/unknown flags/local attention, and clear viewport/latest read proof. The target marker/anchor and fixed bound are local client state, not new server fields. Observable room read-operation idle is emitted even if the POST returns an already-confirmed cursor and no other state changes. A waiting consumer must not hang on that silent outcome.

The denial adapter accepts only an original request matching the current account and room/peer, and same-resource403/404 except CSRF errors. It retires inaccessible content but retains drafts and any interrupted write's unknown state. Missing target IDs alone do not revoke a conversation. These adoption/denial APIs are tested integration points; the dependent native quote host, marker/scroll and error controls are not shipped in this slice. Do not claim the APIs alone make links usable.

## Contracts and privacy

No backend checkout/configuration/history, endpoint, event, response field, HTTP session/CSRF behavior, transport or dependency was changed. The pinned v3.2.1 exclusive-before history and existing exact-ID mutation/file enrichment remain authoritative. History snapshots are not viewport proof or an idempotency key. Room-ignore never becomes DM block; DM disclosure/retention/inspection and generic relationship-unavailable rules remain unchanged. No new background worker/SSE connection, content log, cache, saved-state payload or generated private-content representation is added.
