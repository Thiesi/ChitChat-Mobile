# Cancellation-safe shared policy bootstrap

Discovered while implementing native DM navigation after M4a. Cancelling a real TLS-backed `DirectOperations.context` during its shared `session.php` bootstrap left `SessionState.busy=true` indefinitely; ordinary refresh then refused to run. The deliberate failing regression XML is preserved under ignored `.tooling/bootstrap-cancel-initial-failure`. Room and DM contexts share this path; no backend change or new authentication mechanism is needed.

Bootstrap cancellation now performs local state cleanup in `NonCancellable` under the existing mutex, only if its exact runtime still owns the session. It releases busy and clears CSRF/requires a fresh ordinary bootstrap because response headers/cookies may already have arrived. A cancelled initial connection leaves the CONNECTING state so it can be retried; authenticated identity is not silently logged out. Cancellation is rethrown, not swallowed or retried. Cleanup cannot mutate a signed-out/replacement runtime. Cookies/TLS/rate limits and POST retry rules are unchanged; no credentials/content are logged.
