# M2a: HTTPS and native session authentication

Status: M2a is implemented and locally verified. This is the first M2 slice, not completion of M2 or of the application. [Code PR #6](https://github.com/Thiesi/ChitChat-Mobile/pull/6) merged as `d59d9ce9` after current-head hosted build/journey checks and two complete clean Claude reviews. The acceptance/docs follow-up has its own CI/review gates. Backend source is unchanged at the audited v3.2.1 baseline; the Android base was fetched and matched remote `072ea511` before branching.

## Implemented

- Configurable HTTPS origin with IDN/punycode, IPv6 and explicit ports. Reject raw credential/path/query/fragment input before URL normalization. Session JSON validates compatibility; no invented health/name/capability fields are used.
- Native password form and session state, pending-MFA/recovery form with finite-code warning and remaining count, status/error/retry states, maintenance and unsupported provider/passkey explanations. Registration, account restoration and step-up UI remain M2b.
- One origin/generation-scoped cookie jar, CSRF rotation, no redirects/replayed POSTs/disk HTTP cache/body logs, bounded JSON reads and call timeouts, status/code-aware errors and Retry-After handling. No trust bypass.
- Android Keystore AES-GCM authenticated cookie storage in no-backup space, atomic writes and key/file destruction. Only authenticated non-guest cookies are saved, for at most seven idle days/thirty days from sign-in. Cold start has no cached user identity before server validation. Foreground refresh detects expiry, including anonymous HTTP200.
- Logout clears local state during in-flight requests, retires their cookie callbacks and generations, then makes one bounded server-logout attempt. Unconfirmed remote logout and secure-storage errors are visible. Authenticated/pending sessions must end before changing servers.
- Passwords/recovery codes stay out of saved state and are cleared at submit/background. Test fakes live only in test source sets. The manifest adds INTERNET while retaining TLS/backup safeguards.

## Opt-in live validation

See [the build guide](../build-test-release.md#opt-in-live-authentication-test). Normal unit tests and CI exclude the live test class. `:app:liveSessionTest` alone reads ignored, user-owned `.env.integration`, runs password login/revalidation/repository recreation/logout and attempts the logged-out cookie again. It is never cached and must not print credentials. It does not create accounts or change passwords. It uses an in-memory vault; real Keystore behavior is tested separately on Android. Repository recreation does not prove actual process-death restoration.
