# M4c4b1: scoped exact-message lookup and selection state

This is the shared GET/state prerequisite for notification, search and reply navigation, not a native target screen or notification center. Existing room/DM panes, drafts, read proof and feature-availability copy are unchanged. No backend source/configuration/history, endpoint, event or authentication mechanism was changed or invented.

## Existing backend evidence

Pinned v3.2.1 [room history](https://github.com/Thiesi/ChitChat/blob/4f53ff497f5572072fddad42d8ac3979e9cdf0d1/src/Room/MessageService.php#L52) and [DM history](https://github.com/Thiesi/ChitChat/blob/4f53ff497f5572072fddad42d8ac3979e9cdf0d1/src/DirectMessage/DirectMessageService.php#L173) accept arbitrary positive exclusive `before_id`. Fetch at most50 rows with `before_id=target+1`; at maximum signed ID omit before. Reuse current exact-ID mutation/file enrichment and retain raw pagination evidence even when enrichment omits the target. Deleted tombstones remain available; a missing ID is unavailable, never the nearest earlier row or a successful newest-page fallback. This requires no around-message endpoint or newest-to-oldest traversal.

Private ping lookup uses only the existing latest100 records and viewer/room authorization; older missing pings are unavailable. Room detail may be fetched when absent from the directory; this neither joins a room nor grants history access. DM lookup preserves required non-E2EE/retention/inspection disclosures and generic messaging-unavailable semantics, not an inferred reverse block. Room-ignore policy must never suppress DMs.

## Shared session and target actor

`MessageTargetOperations` exposes session state and one lookup, with typed numeric room/message, room/ping and peer/message targets. `SessionMessageTargetRepository` captures the original rendered SessionState and capability across bootstrap, context, history and metadata. The existing `refreshedAccess(expected)` now checks that capability inside the runtime-selection mutex too: a queued old lookup cannot bootstrap a replacement account. Public refresh behavior and the shared transport remain unchanged. Direct privacy validation is extracted without changing its existing rules.

Validate positive IDs, no self-DM, exact target ID AND room/peer namespace, participant perspective and current account/server/generation/session version. Missing ignore/mute policy fails before conversation content GETs. Rebind current policy after the final await (including vault persistence) and before consumption; late GETs cannot restore an old ignore/mute state. Session retirement cancels requests. No read acknowledgment, presence/typing, membership, message POST, new SSE connection, background service, log, content cache or saved-state payload is introduced.

`MessageTargetViewModel` is a main-confined, cancellable selection actor with an opaque original-request reference, monotonic attempt fence, explicit loading/error/unavailable state and manual retry. Start only in foreground after session work is ready. Background cancels GET work and drops private result bodies; foreground reconciles the retained numeric selection. Account retirement clears it. A late non-cooperative predecessor cannot overwrite a successor; old Cancel/Retry/Consume callbacks cannot act on the replacement selection. No emission-triggered failure loop or duplicate configuration-foreground request is allowed.

Consumption is single-use and requires current scope, fresh validation, an exact available target and no session/storage uncertainty. It rechecks current policy; an ignored ping becomes unavailable and unknown policy fails explicitly rather than using an old snapshot. State/snapshot/request have no generated private-text representation. Test-only snapshots and network fixtures are not production fallbacks.

## Dependent native consumer contract

The next slice must expose loading, unavailable/deleted/unauthorized and Retry/Cancel states, then adopt only the exact consumed snapshot into the normal room/DM pane after another original-scope/policy fence. Use fixed historical upper bounds, preserve drafts/unknown-send flags and raw cursors, scroll/highlight the exact ID and offer an explicit Jump latest. A target GET is not visible latest-window proof, an unread acknowledgment or explicit uncertain-send reconciliation. It must not silently mark newer messages read, force room membership, evict drafts or replay a POST. Existing native notification/push availability remains pending until its real consumers ship.
