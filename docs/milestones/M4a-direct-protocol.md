# M4a: existing-session direct-message protocol prerequisite

Typed client protocol only: the native inbox/conversation remains M4b. This does not enable a fake screen or advertise functional DM UI. Existing [v3.2.1/4f53ff4](https://github.com/Thiesi/ChitChat/tree/4f53ff497f5572072fddad42d8ac3979e9cdf0d1) contracts; no backend writes/new endpoints, credential mechanism, database or transport.

## Contracts and client policy

`DirectOperations`/`SessionDirectRepository` share PHP cookies, CSRF, origin/TLS, bounded JSON, cancellation, rate handling and generation-bound `SessionAccess`. Room/DM contexts reuse `refreshedAccess` for normal bootstrap/policy refresh without acquiring a replacement identity. Optional typed session privacy remains memory-only and clears on authentication changes/logout. Missing/unsupported DM privacy disables that feature without inventing an E2EE promise or logging out otherwise compatible room access.

- [Search/list/history/send/read](https://github.com/Thiesi/ChitChat/blob/4f53ff497f5572072fddad42d8ac3979e9cdf0d1/src/DirectMessage/DirectMessageService.php#L34): bounded prefix search (the existing SQL LIKE underscore semantics are retained),100 most recent conversations without pagination, ascending exclusive-before history, perspective-correct sender/recipient, exact201 send acknowledgment and whole-peer read count. No automatic POST replay. DM slash text is literal; trim/4000 Unicode-codepoint validation differs from room commands.
- DM wire mentions lack room `broadcast`; quoted targets lack room `type`. Separate wire types match actual [hydration](https://github.com/Thiesi/ChitChat/blob/4f53ff497f5572072fddad42d8ac3979e9cdf0d1/src/DirectMessage/DirectMessageService.php#L503); no fake room IDs or guessed response fields. Public canonical models are explicitly client-enriched and have no generated content-bearing strings.
- History and inbox previews require current [mutation metadata](https://github.com/Thiesi/ChitChat/blob/4f53ff497f5572072fddad42d8ac3979e9cdf0d1/src/DirectMessage/DirectMessageMutationService.php#L43) and authorized [attachment metadata](https://github.com/Thiesi/ChitChat/blob/4f53ff497f5572072fddad42d8ac3979e9cdf0d1/src/DirectMessage/DirectMessageAttachmentAccessService.php#L36). Preserve raw cursor/count evidence when enriched rows disappear during retention. Literal `Message deleted.` is not a deletion flag. Validate pair/perspective/order/IDs and reject unsolicited metadata. File bytes/upload/download remain M5; one file per message is the actual unique constraint, not an assumption.
- Send returns a validated confirmed ID, not a misleading unenriched row. A subsequent GET failure must not turn a confirmed POST into unknown delivery. M4b clears an acknowledged draft, then refreshes canonical history; ambiguous POST failure retains draft/explicit reconciliation and duplicate-risk policy.
- [Blocking](https://github.com/Thiesi/ChitChat/blob/4f53ff497f5572072fddad42d8ac3979e9cdf0d1/src/DirectMessage/DirectMessageBlockService.php#L36) exposes only own block/generic messaging availability. Either direction stops sends; unblock removes only one's own flag. Existing history/read remain available. Room ignores/mutes must not be reinterpreted as DM blocks; only global mute applies to DM sending.
- Fresh [session privacy](https://github.com/Thiesi/ChitChat/blob/4f53ff497f5572072fddad42d8ac3979e9cdf0d1/public/api/v1/session.php#L79) supplies non-E2EE, retention, inspection and separate revision-review policy. Preserve retained-edit/delete warnings and the actual participant-notification flag; B5 already tracks its discrepancy. Do not infer inspection rights from this disclosure.

The shared response bound now accommodates actual bulk payloads: PHP [escapes Unicode](https://github.com/Thiesi/ChitChat/blob/4f53ff497f5572072fddad42d8ac3979e9cdf0d1/src/Http/JsonResponse.php#L22), so100 rows with4000 supplementary codepoints and full quoted bodies exceed9MiB. Only room/DM history, DM previews and mutation success batches allow16MiB/25seconds. Small/auth/error JSON remains1MiB; exports retain their separate16MiB/120seconds. Larger batches fail explicitly without invalidating the session; no unbounded buffering. Private pings remain1MiB because their100×500-codepoint contract fits it.

`read` sends only `{user_id}` and returns `{updated}`, never an invented rendered through-ID. The race fixture shows a newly arriving message can already have `read_at` after a whole-peer acknowledgment although it was never rendered. M4b must refetch after the POST and maintain separate local unseen/new attention, not relabel it a restored server unread count. Notifications/other-device read/block changes need entry/foreground/periodic refresh despite absent SSE signals. Guests remain unsupported for DMs.
