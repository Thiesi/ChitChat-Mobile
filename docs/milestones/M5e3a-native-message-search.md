# M5e3a: native participant-search screen

This consumer adds a real member-only Search messages destination on delivered PR77/78. Users can submit literal terms, choose All/Rooms/Direct, inspect plain-text room/DM excerpts and use explicit Previous/Next/Retry/Cancel. Opening the canonical original remains a separately disclosed M5e3b consumer; cards do not navigate, mark reads, send messages, publish typing or create notifications.

## Privacy and root boundaries

Search routes contain only encoded server/account/generation/version ownership, never terms, excerpts, usernames, cookies or selected result bodies. Restored/stale owners are rejected. Root lifecycle/actual-entry checks own entry opening, navigation close and configuration/background decisions; screen callbacks retain original entry/request/page references. Same-entry recreation retains ViewModel work, while genuine background/owner retirement clears private query/results. No query/state is placed into SavedStateHandle, bundles or disk.

All/Direct search additionally requires the existing validated current-server DM privacy model. The repository checks that model both before and after the HTTP await; unknown/unsupported policy cannot return private DM results. Rooms-only search is independent. The screen rebinds current policy, hides non-room-scope results if it becomes unavailable, and provides an explicit Refresh session option. It never invents policy defaults or automatically repeats a search after refresh/resume. The shared DirectPrivacyNotice is exposed internally for presentation reuse only; current-server non-E2EE/retention/inspection/revision disclosures remain authoritative. Search itself acknowledges no chat/notification reads.

## Interaction and layout

Keep the query,48dp Search/Cancel and options together above the result scroller. Options holds explicit scope choices, privacy and refresh controls. The root compact-input treatment also applies to Search so the realtime toolbar cannot consume its keyboard viewport.48dp Previous/Next arrows and page number use fixed-size accessible controls, including RTL direction; the page limit explains refining terms.

Only result captions are visually ellipsized; the actual input/request remains intact, with M5e2's explicit memory-limit rejection. Native input remains an ordinary single-line text field with explicit Search action; no focus/IME request, tap replay, longer deadline, hidden readiness check or tracing is added. Result excerpts use Text, not MessageBody/HTML/highlight/link parsing. Null room senders are labelled unavailable rather than inventing an identity. Shared date/clock formatting respects the current account/device settings.

Result/pagination composition is keyed by the original result reference; inner lazy keys are bundle-safe namespace/message IDs. Retry and Cancel use their original attempt keys; Search uses the rendered draft/scope. This retires held presses when actions change rather than relying on a reused Compose clickable node's updated callback. Edited input remains distinct from the completed search caption/page context.
