## New bounds and privacy

- CI starts a host-side logcat reader before the build/native command. A bounded read of device time supplies its start timestamp, avoiding stale previous-run records or host-clock assumptions. No pre-tap readiness wait or input-pipeline interception. The original Gradle command runs exactly once.
- The existing fixed tag/package/event/phase/reason/test-identity allowlist is unchanged. Raw records are filtered before buffering; whole overlong records, including suffixes, are dropped. No raw file or arbitrary fallback. At most2000 safe records precede the first test failure; that context is frozen with at most200 later records. Without an observed failure, retain only the bounded recent window. Later tests cannot evict the first failure.
- `app/build/reports/androidTests/device/ime-lifecycle.txt` and `.status.txt` are uploaded by the existing report artifact, including on a successful gate. Fixed counters/error codes disclose missing/early-ended/failed collection; no exception payloads. Collector start/read/cleanup/write failures never replace Gradle's exit status. Owned collector termination/join waits are bounded, with kill fallback; no adb-server/device restart or retry.
- Failure-only `input_method` capture streams at most1MiB in4096-character chunks/lines, retains at most40 existing fixed flags, and records character count, truncation, discarded overlong lines and observed service-timeout marker. Complete tokens across reads are preserved; cap-split unterminated lines are unknown. No-progress/read errors become unavailable capture at the boundary. Raw chunks/lines are transient, never the full retained dump. Window-type parsing keeps its existing64KiB bound and ambiguity handling.
- The two server snapshots remain sequential, taken after timeout/before cleanup, not atomic deadline proof. Nullable metadata stays unknown. A successful path performs no server dump. These diagnostics are for synthetic credential-free fixtures, not uploading private conversation/device logs.
