# M5d1: bounded message-formatting parser

This independently buildable prerequisite supplies ephemeral native formatting data. Room/DM transcripts still display their existing plaintext; Compose rendering, link activation and accessibility/device acceptance follow separately. Existing in-app availability disclosures remain accurate. PR71 and its failed native gate are independent and unchanged.

## Browser contract

The reference is ChitChat v3.2.1, commit `4f53ff497f5572072fddad42d8ac3979e9cdf0d1`, [message-format.js](https://github.com/Thiesi/ChitChat/blob/4f53ff497f5572072fddad42d8ac3979e9cdf0d1/public/assets/js/message-format.js), Git blob `25f07f89a8dfabc9047e77a4b82281575e883a3c`. The port retains its [BSD-2-Clause notice](../licenses/chitchat-message-format.txt).

Supported syntax is `*strong*`, `**strong**`, `_emphasis_`, inline backticks, fenced code, consecutive `>` quote lines and HTTP(S) links. It is a small plaintext grammar, with no HTML interpretation, general Markdown, named links or extra escapes. Browser delimiter boundaries, ECMAScript whitespace and malformed-marker literal behavior are preserved. A fence's opening suffix is literal code, not a language identifier. CR-containing quote lines remain ordinary paragraphs, matching the pinned browser parser.

Username-shaped mentions remain text. Parsing cannot invent server-authorized mention IDs, colors, user targets or click actions. Formatting data is separate from literal message bodies, reply/copy text and canonical server rows. No existing transport, session, read/send consent or reaction/author actor changes.

## Native limits and links

`MessageFormatting` is stateless and performs no I/O. Content-bearing objects have constant debug strings, no cache, persistence, account scope or saved-instance representation. Consumers must retain their existing owner/canonical guards.

The parser caps interpretation at16,384 UTF-16 units,4096 nodes,16 nested levels and1024+32 times input-length scan units. Exceeding any bound returns the complete original body as one literal node with `literalFallback=true`; it neither truncates nor publishes a partially linked tree. This is deliberately more conservative than the browser for adversarial input. Ordinary4000-code-point server messages fit the input bound. The fence lookup is precomputed and marker scans share a per-call budget.

Link candidates use the existing OkHttp URL parser. Only explicit HTTP(S) prefixes qualify. Credentials, controls and unsupported URLs stay literal, including their formatting markers. Canonicalization outside the shared supported corpus can differ from the browser's WHATWG URL implementation. Plain HTTP, local hosts and private IPs are data candidates, with no permission to use authenticated session transport or browse. A future native consumer owns explicit activation and navigation policy; this slice launches nothing.

## Verification and reproducibility

`MessageFormattingBrowserTest` checks both inline and block ASTs against137 golden cases generated by the hash-verified pinned browser parser:73 named grammar/boundary cases and64 seeded combinations. The [generator](../../tools/generate-message-format-fixtures.mjs) verifies the reference Git blob before evaluating it. Download the pinned reference to an Android-owned temporary file; do not fetch into the sibling backend checkout. With Node:

```text
node tools/generate-message-format-fixtures.mjs <reference-file> <new-output-file>
```

The output must equal `app/src/test/resources/message-format/browser-cases.json`. The generator refuses to overwrite an existing output. JVM tests never download, execute JavaScript or contact a server. Additional tests cover conservative URL rejection, complete literal fallback for input/work/node bounds, mixed nested styles, full Unicode bodies, per-call isolation and privacy-safe debug strings.

The first focused run passed all137 browser cases but failed an invented deep-nesting test: repeated same-marker wrapping closes earlier under the actual browser grammar. Its failed XML/HTML/logs and original fixture are retained in ignored local evidence. The corrected test asserts actual mixed-style recursion, with no production parser change to obtain a pass.

Before delivery require the full local JVM/lint/debug/release gates, complete current-head unfiltered/untraced Linux/API36 native CI and written initial/fresh Claude review. This prerequisite supplies no native rendering, physical/API26/live acceptance, keyboard fix, diagnostic replay or release waiver. Exact run results belong on its PR.
