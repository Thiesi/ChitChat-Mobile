# M4b2: native direct-message consumer

This slice consumes M4a's existing-session protocol and M4b1's bounded canonical state. It adds a native inbox, prefix recipient search, thread, multiline explicit sending, own blocking, privacy/read-race disclosures and account-scoped navigation. No WebView, alternate authentication, guessed endpoint or production fake. The audited backend is ChitChat v3.2.1 at `4f53ff497f5572072fddad42d8ac3979e9cdf0d1`; no backend source was changed.

## User behavior and synchronization

Home opens the inbox for authenticated non-guests. Canonical previews retain deletion/file metadata, outgoing perspective, account date/clock formatting, capped server unread counts and separately labelled non-durable local attention. Prefix search is explicit, including the keyboard Search action. The server limits the inbox to 100 conversations; saved in-memory drafts remain separately reachable with explicit discard confirmation and no silent eviction. Recipient names never authorize navigation.

Routes carry server/account/session-generation/version identifiers, not bodies or secrets. Validate the complete scope before composing a consumer; recheck selection callbacks and pop to Home on any mismatch, including authenticated-to-authenticated replacement. Logout clears both engines' private state. Rotation uses ViewModel memory, not persisted bodies or searches.

Conversation details expose the fresh non-E2EE, retention, inspection and revision-review policies, including reasons/auditing/participant notices where configured. Block/unblock is explicit and confirmed; the UI never infers another person's block or treats ignoring as blocking. Global mute and generic unavailability disable send while allowing authorized history/read access. An uncertain send keeps its draft; automatic events/resume never grant duplicate-risk consent. A known send ID clears the draft before fallible history refresh. An unknown block requires explicit reconciliation.

Only foreground consumers synchronize: screen entry, canonical invalidations from validated SSE hints, reconnect and a one-minute STARTED refresh. Raw event messages are never authoritative display state. No permanent background connection/service or background polling is added. Queued invalidations drain after writes; read/send/block POSTs are not cancelled or replayed to service an event. Session busy, refresh-required, secure-storage and rate-limit states are explicit; expiry re-enables the action without editing or automatically posting.

Stable message keys and ID/offset anchors preserve an away viewport when paging or refreshing. New messages, including outgoing messages from another device, offer an explicit jump rather than forcing scroll. Retention, incomplete canonical coverage and empty fixed ranges have distinct explanations. The bounded engine may evict rows, not secretly join disjoint ranges. The composer uses native multiline input, system keyboard and an explicit visible Send action. A Material-decorated basic text field uses compact padding without changing the input component on IME resize. In constrained height the details/status controls move to a badged accessible composer action, including initial network/policy failure without a context; shared feedback rendering keeps all recovery/consent actions available. Multiline editing remains supported even when only one line fits.

Read acknowledgment requires a RESUMED, focused, unobscured transcript at the live edge with the canonical newest row's actual bottom visible. A tall row need not fit entirely; zero-height/off-screen rows cannot qualify. STARTED network synchronization alone is insufficient. The same focused/bottom-read guard is shared with room transcripts, including the room private-ping overlay. Whole-peer read still cannot atomically acknowledge only rendered messages: refetch after the POST, preserve labelled local attention for races/unrendered arrivals, and explain additional possible acknowledgments rather than fabricating a server count/cursor. Dialogs must not acknowledge content behind them. Dismissing a dialog cannot jump to or read a new row below a preserved anchor.

## Remaining scope and acceptance

M4c supplies typing and bilateral preferences, ignore management and the durable notification center. M5 supplies author reply/edit/delete/reaction actions, formatting, attachments/downloads/sharing, search and exact-target navigation; this consumer already renders canonical read-side quotes, deletion, edit markers, reaction counts and attachment metadata, not those actions. Push remains unavailable until M6's UnifiedPush work. Room presence is not synthesized by opening a DM.

Fake-native journeys, emulator inspection and CI are not end-to-end DM acceptance. Live two-account send/read/block, API 26, device/TalkBack, full manual font/IME/landscape and real notification acceptance must be recorded separately when authorized and performed. No claim of full application or push completeness follows from this slice.
