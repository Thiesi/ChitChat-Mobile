# M3c2: foreground session-event runtime

This slice connects the M3c1 shared-session SSE transport to the actual Android process. It provides native connection/error status, immediate session invalidation through the existing session repository, and readable/dismissible server announcements. It does **not** yet automatically reconcile the directory or room transcript. Those screens retain their explicit manual-refresh disclosure until M3c3 connects their canonical-read consumers. No live SSE, message, read, presence or membership acceptance is claimed from fixtures.

## Lifecycle and event ownership

- `ChitChatApplication` owns one `RealtimeCoordinator`, its supervised main-dispatcher scope and the existing `SessionRealtimeRepository`. There is no second authentication client or copied credential, Activity-owned stream, background service or periodic WorkManager substitute.
- [ProcessLifecycleOwner](https://developer.android.com/reference/androidx/lifecycle/ProcessLifecycleOwner) starts/stops the runtime; its delayed stop excludes Activity configuration recreation. `AndroidRealtimeRuntime` owns one foreground-only default-network callback and removes it on stop. [Android network callbacks](https://developer.android.com/develop/connectivity/network-ops/reading-network-state) report availability, not successful HTTPS/server reachability. Do not require Google's Internet-validation capability for a private self-hosted LAN installation. HTTP/TLS remain authoritative.
- An authenticated server/account/generation/session-version identity fences callbacks. Ordinary busy bootstrap does not pretend to be logout; a new connection waits for readiness and server cooldown. Account transitions clear cursor, selected room, presence users and announcements. Nothing is saved to bundles, disk or logs.
- The current server normally closes streams after25 seconds and advertises1000ms retry. Normal EOF reconnects after that verified hint; failures use bounded exponential jitter/Retry-After. An explicit40-second watchdog bounds the pinned library's disabled full-call timeout. Background/offline state cancels streaming and retries. TLS, redirects and malformed/incompatible payloads stop with a deliberate Retry action, never a trust bypass.
- A bounded mailbox serializes state changes. Validate known room/ping/reaction/presence/broadcast payloads before advancing the cursor; IDs have legal gaps and are never chat/read IDs. Unknown additive events and absent/slow subscribers increment an in-memory reconciliation version before acknowledgement rather than silently losing the need to refresh. Reopen/resume and periodic foreground reconciliation also increment it. This version is only an invalidation hint until M3c3 consumes it, not a transactional history cache or evidence that a screen is current.
- Event subscribers must be cancelled/recreated with their session generation and reconcile canonical state on scope entry. SharedFlow is a bounded, nonpersistent delivery hint, not an account-independent event store. No POST is replayed to recover an event or connection.
- Broadcasts remain separate from chat rows, notification/read cursors and unread counts. Retain at most20, preserve their server timestamps, filter room-scoped notices and provide a native full-text dialog/dismiss action. Maintenance broadcasts have `message` and optional `lockdown`, not a required ordinary sender. The entire private announcement/dialog disappears when account state clears.

## Presence policy prepared for the room consumer

The coordinator supports the actual CSRF heartbeat and aggregate-list contracts, serialized/conflated20-second renewals, explicit activity, warning/expiry and reentry. M3c2 does not select a production room or acquire a room lease; M3c3 supplies its permission-aware UI and acknowledged-send hook. Cleanup must not create a presence row merely because an authenticated user visited home.

Only explicit room selection/reentry/Stay and acknowledged sends/pings may count as deliberate interaction; never typing, scrolling, SSE or passive foreground restoration. An expired room stays expired until explicit successful reentry. Genuine background or uncertain connectivity deliberately deactivates presence while retaining the selected route/draft for a later **Return to room** action; rotation is not background. Otherwise a new/pruned server row would reset idle even with `interacted:false`. Rotate UUIDs across uncertain epochs, serialize writes, fence late results and use bounded best-effort null cleanup only for a possibly acquired room lease. No credential retention or lifecycle wait is introduced. Aggregate invalidations re-read the list, never invent user deltas.

The verified backend remains [v3.2.1 /4f53ff4](https://github.com/Thiesi/ChitChat/tree/4f53ff497f5572072fddad42d8ac3979e9cdf0d1), including [stream](https://github.com/Thiesi/ChitChat/blob/4f53ff497f5572072fddad42d8ac3979e9cdf0d1/public/api/v1/events/stream.php), [presence](https://github.com/Thiesi/ChitChat/blob/4f53ff497f5572072fddad42d8ac3979e9cdf0d1/src/Presence/PresenceService.php), [typing](https://github.com/Thiesi/ChitChat/blob/4f53ff497f5572072fddad42d8ac3979e9cdf0d1/src/Realtime/TypingService.php), [broadcasts](https://github.com/Thiesi/ChitChat/blob/4f53ff497f5572072fddad42d8ac3979e9cdf0d1/src/Realtime/BroadcastService.php), [room mutations](https://github.com/Thiesi/ChitChat/blob/4f53ff497f5572072fddad42d8ac3979e9cdf0d1/src/Room/RoomMessageMutationService.php) and [room reactions](https://github.com/Thiesi/ChitChat/blob/4f53ff497f5572072fddad42d8ac3979e9cdf0d1/src/Reactions/RoomReactionService.php). Direct-message events are only positive-ID invalidation hints until M4's full typed consumer; no DM presentation is claimed.
