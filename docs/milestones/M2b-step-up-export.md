## Contracts and usable flow

- `public/assets/js/step-up.js:withPrivilegedStepUp`, `src/Auth/SessionManager.php:requirePrivilegedStepUp`: run the requested action first; only definite403/step_up_required leads to explicit verification and one retry. Second rejection, cancellation, network ambiguity and other permission errors never loop/replay.
- `public/api/v1/account/mfa/status.php` and `account/identities/list.php` discover MFA, remaining emergency codes and whether a password exists. Missing metadata fails rather than guessing. MFA accounts cannot use password step-up; a policy upgrade refreshes methods without weakening authentication.
- `public/api/v1/step-up.php` receives `{password}` and returns `privileged_step_up`. `mfa/step-up-recovery.php` receives `{recovery_code}` and returns nested `security.privileged_step_up` plus `recovery_codes_remaining`. Require200, active expected method, valid timestamps/lifetime. Remaining codes update shared state; an uncertain recovery request is never repeated and may have spent a code. The user must explicitly choose emergency fallback and sees its finite-code/cancellation warning.
- `public/api/v1/account/export.php`, `src/Account/PersonalDataExportService.php`: authenticated CSRF POST, recent step-up, five requests/hour and an audited complete retained-data snapshot. Typed transport validates the format version/name and account ID, tolerates future fields, and saves only `export`, not its envelope. Other participants’ private data/excluded bytes stay governed by the server; no extra client endpoint/authorization is inferred.
- Account navigation is authenticated and native. The common session jar, CSRF, TLS and cancellation policy are reused through generation/account/version-bound access. An authenticated401 invalidates globally; ordinary resource validation/403 does not. Cooldown and lifetime checks apply below UI too. No secret-bearing data-class strings, request logging, alternate auth system or Firebase dependency was added.
- SAF creates a new JSON destination before the private download. Old-generation picker callbacks cannot export a new account’s data. The synchronous server response has a bounded16MiB/120-second client path; larger histories receive an explicit browser-use explanation, not a partial successful export. Serialization runs off-main; provider writes check cancellation/authorization every32KiB. Buffer clearing is best effort, not a promise of zero copies in managed memory. No app-owned payload file or persisted URI grant exists.
- The chosen export is unencrypted, may use cloud storage and survives logout. Failure/cancellation can leave an empty/incomplete document, disclosed before starting and never automatically deleted. Passwords/codes are non-saveable and cleared on submission/background. Navigation/genuine background/logout cancel pending verification/network/write; configuration recreation retains the Activity ViewModel's request without resubmission, and navigation restoration must not cancel it at its initial null route. Account changes retire the picker registration. Unsupported passkey/provider accounts receive truthful browser-separate-session guidance, not a fake native handoff.
