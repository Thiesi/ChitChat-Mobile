# M4c4b2: native reply-to-original navigation

Room and DM reply previews open an exact authorized original message in the normal conversation pane. This is a concrete consumer of [M4c4b1](M4c4b1-message-target-state.md) and [M4c4b2a state/scope corrections](M4c4b2a-target-adoption-state.md), not a debug ID form, browser wrapper, alternate read-only transcript, notification center or push implementation. Reply composition, search and cross-conversation notification routing remain separate work. The combined state/native working diff exceeded126000 UTF-8 bytes, so the prerequisite and preserved native consumer have independent complete gates/reviews; nothing was silently dropped or truncated. Existing [v3.2.1 exclusive-before history](M4c4a-notification-contracts.md#native-destinations-are-hints-not-completed-navigation) and mandatory metadata enrichment are unchanged; no backend checkout, endpoint, event, response field or authentication mechanism was changed/invented.

## User behavior

An available quote has a native48dp-minimum action with a bounded plain-text preview. A deleted but retained original remains visitable with deleted-message copy; missing/inaccessible quotes are not falsely presented as found. Selection shows cancellable progress, clear unavailable/incompatible/connection/session/rate-limit states and explicit Retry. The successful exact ID is scrolled to and marked with both text and selection semantics, not color alone. The normal composer/draft and existing privacy/ignore rules remain in place. Jump latest is explicit; lookup/adoption never acknowledges chat reads or grants uncertain-send reconciliation/consent.

Current consumption is deliberately same-room/same-peer. The root owns one lookup actor and dialog, checks the real current navigation entry plus original server/account/generation/session version before handoff, and never navigates automatically from an event. An accept/reject callback keeps the original selection while a conversation write/read is busy; old Cancel/Retry/completion callbacks cannot retire successors. Entry, modal and genuine-background behavior reuse the existing lifecycle/session transport. Private result bodies are dropped on background and the retained numeric selection is reconciled on return; no permanent service, new stream, saved-state payload or disk content cache is added. Configuration restoration does not manufacture another POST.

## Historical, privacy and write boundaries

Both panes adopt a fixed historical upper bound, exact target marker/anchor and raw older cursor. The prerequisite retains that bound even after retention removes every row, across foreground, canonical invalidations and manual refresh; it cannot accidentally widen to latest. Native empty historical room copy explains the missing range and explicit Jump latest, rather than falsely claiming the entire room has no messages or that a nonexistent nearest row is visible. Lost targets/anchors are explained. Ignore presentation remains room-only and does not reveal a collapsed author automatically; DMs retain fresh non-E2EE/retention/inspection and mute/relationship context.

Rebind current policy again at adoption, fence every original scope, clear old-account content while collectors catch up, and preserve drafts/local attention and delivery-unknown flags. A target GET is not the explicit latest-history check needed before another uncertain send. A deliberate check of latest history retains the existing explicit duplicate-risk flow; no message/read/block POST is replayed. Observable room read-operation state lets the consumer wait even when a read returns an already-confirmed cursor without changing other state.

Confirmed same-resource403/404 (except CSRF errors) retires inaccessible transcript/context, without destroying the draft. A cancelled in-flight write remains unknown; this security retirement is distinct from cancelling a write just to serve a lookup. Missing exact IDs alone do not revoke the whole conversation. Original-request and current-pane guards prevent an old denial from clearing a successor. Native input/send and DM block callbacks also bind their original rendered session and room/peer: an old pane cannot edit/send another pane's retained draft or block its recipient. Typing input is published only after a scoped draft edit is accepted; the lookup modal suppresses read/typing proof.
