## Boundary

The shared `tapNativeInput` catch path now snapshots the server **after the original assertion timeout but before throwing into test cleanup**. Successful input paths do not run a command or gain an extra wait. Existing failed assertions remain failed; the original timeout is retained as their cause. The client-side inset/session observations are frozen before the server read, so a later teardown or asynchronous state change cannot relabel them.

The sequential `dumpsys -t 2 input_method` and `dumpsys -t 2 window windows` calls each bound the service wait. Each reads at most65,536 transient characters before closing its descriptor and retains at most40 fixed fields. The window filter selects exactly one window by `mAttrs`'s INPUT_METHOD/2011 type, never by its title; missing/ambiguous windows stay unknown. Other-window fields are discarded. Only fixed Boolean fields and the [AOSP draw-state enum](https://raw.githubusercontent.com/aosp-mirror/platform_frameworks_base/android16-release/services/core/java/com/android/server/wm/WindowStateAnimator.java) survive; unknown states stay omitted. No raw dump, title, EditorInfo, account, text, exception or arbitrary fallback is stored/logged. Unknown fields, permission failures and unsupported formats become unavailable (`flags=null`), not a false hidden-state claim. Separate start/finish uptime and limit indicators describe each observation; they are not an atomic snapshot. Reads can affect timing **after an already failed assertion**, never establish a production fix.

Use only synthetic test fixtures. The explicit collector self-test also invokes it to validate safe capture; that is not an input readiness check. It never requests focus, calls IMM getters that flush focus, shows/hides/restarts input, retries taps, changes settings or repeats a failed gate.
