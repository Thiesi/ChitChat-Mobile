## Contracts and behavior

The independently verified [protocol prerequisite](M3a1-room-protocol.md) is published first; this native consumer remains separately buildable/tested against it. Neither PR substitutes its checks for the other.

- `GET rooms/list.php` returns `{rooms:[...]}` with membership/invitation, guest/age/inactivity policies and capped unread/read metadata. `detail.php?room_id=42` returns `{room:...}` without list-only unread fields. Detail lookup supports a known unlisted room ID; it does not broaden discovery rights.
- `POST rooms/join.php` receives `{room_id:42}` and returns200 plus the joined room. Private invitations are consumed by joining. Invitation permits metadata, not private history. Minimum-age and birth-date checks remain authoritative on the server; staff viewing rights do not imply age bypass for joining.
- `POST rooms/leave.php` returns200 and `{status:"left"}`. The immutable owner cannot leave; other members explicitly confirm leaving. Membership is distinct from active presence; this slice sends no presence or read acknowledgments and never marks messages read by visiting the directory.
- `POST rooms/create.php` returns201 and an owned room. Only non-guest `super_admin`, `admin`, or `chat_admin` gets the native form, while the server still enforces authorization. All editable creation fields are represented. Shared validation matches PHP trimming, key normalization, Unicode code-point limits and guest/age/visibility/inactivity restrictions; invalid combinations are explained, not silently reset.
- The existing `SessionHttp` and generation-bound `SessionAccess` own origin/TLS/cookies/CSRF, cooldown, lifetime, cancellation and error handling. No parallel client or auth mechanism exists. Wire validation checks IDs, required policy fields, schema/status, joined/owned responses and duplicate list IDs. Resource403 stays local; authenticated401 invalidates globally. Sensitive metadata remains in account-scoped memory only, never logs, saved-instance state or a plaintext disk cache.
- The native Rooms destination has a lazy list, membership/invitation labels,99+ unread presentation, room detail and creation dialogs, known-ID lookup, loading/empty/stale/retry/error states and accessible controls. ViewModel memory preserves drafts across configuration recreation and clears them on server/account/generation/version changes. Genuine background/navigation cancels requests; configuration recreation does not.
- Mutation results are never automatically replayed. Cancelled/ambiguous writes show an unconfirmed state and require explicit GET reconciliation before another mutation. This does not prove whether an unacknowledged create was audited/applied; room-key uniqueness and clear warnings remain important. Failed reads preserve only clearly stale existing metadata. Late callbacks are fenced by request sequence as well as account identity.
