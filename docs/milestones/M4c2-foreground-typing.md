# M4c2: foreground typing in native conversations

This vertical slice connects native room/DM composition, the existing typing POST and the existing authenticated foreground SSE stream. M4c1's account-wide bilateral preference remains authoritative. There is no new backend API, background connection, relay, message-text transmission, message/read cursor or notification transport.

## Scope, lifecycle and expiry

`TypingOperations` reuses original-session access, cookie/CSRF transport and authorization/backoff. Local suppression makes no HTTP call and does not falsely renew saved-session validation time. Signals are best effort; failures/suppression count against the throttle and never schedule automatic POST replay. Stored drafts, focus alone and resume do not publish. Only actual native input callbacks pass a content-eligibility Boolean, not message text, to the coordinator.

One process-owned main-confined coordinator consumes the existing SSE flow; it opens no stream itself. Selection is fenced by server/account/generation/version and target. Each identity gets a fresh subscriber, retiring any previous subscriber's buffered queue; cached replay is not accepted as fresh typing evidence. RESUMED, focused, eligible screens own selection; pause/disposal/background/offline/privacy loss retire hints and pending ephemeral requests. Disposing an older target cannot retire its successor. Returning users must actually type again to publish. Other clients' already delivered hints fade by the existing expiry; there is no claim of immediate remote revocation.

Validate actor/name/room before cursor acknowledgement. A local monotonic receipt timestamp on `RealtimeEvent` is client metadata, not an assumed server response field; it expires queued hints without requiring synchronized server/device wall clocks. Duplicate IDs do not renew expiry, message arrivals remove their sender, and at most100 transient names are kept. No names or typing state go to disk/saved state/logs. Rendered state also carries explicit account scope, so the UI rejects stale source emissions even if their numeric room/peer matches a replacement account.
