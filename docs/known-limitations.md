Original failures and a separate local SystemUI ANR remain preserved; no production authentication fix or exact hosted IME-mechanics claim. Private-ping issue16 remains separate.

- M4a/b1/b2 supply shared-session DM protocol, bounded canonical state and native inbox/search/thread/composition/privacy/blocking/foreground consumers. Missing/unsupported privacy disables DMs without guessing or invalidating room access; no fixture is a production fallback. Typing/ignore management/notification center remain M4c, author actions/media/search M5 and push M6. See [consumer evidence/acceptance](milestones/M4b2-native-direct-messages.md); live two-account DM acceptance remains unperformed.
- Server DM inboxes cap at 100 conversations. Whole-peer read cannot atomically acknowledge only visible messages; separately labelled bounded local attention is non-durable and cannot repair server/cross-device unread state. In-memory drafts cap at 100 peers with explicit discard, not silent eviction. No messages/drafts/searches persist across process death. Read-side attachment/reaction/quote metadata is not implemented file/action UI.

- M3c3b adds foreground room realtime/presence; [evidence](milestones/M3c3b-room-realtime.md) distinguishes fixtures from pending authorized live two-account acceptance. Drafts/content remain memory-only. Advanced tools/media remain M5.

M2a normalizes Unicode hostnames with OkHttp and rejects credentials/raw paths before normalization. Private/loopback HTTPS origins are intentional for self-hosting, with mandatory valid TLS verification. Repository/Keystore recreation tests do not establish Android process-death acceptance. Platform dark-startup flash/account-palette synchronization remain later polish.

- M1/M2a/M2b1 are merged. M2b2 implements shared password/emergency-recovery step-up and personal JSON export through SAF; [current evidence](milestones/M2b-step-up-export.md) separates checks from pending acceptance. Rooms and DMs have foreground native consumers, not complete chat/push parity or live acceptance. M2 live acceptance and the application are not complete. Live disposable-account mutations require separate approval; fixture registration/restoration does not prove those end-to-end flows.
- Export response size is bounded to16MiB, with a120-second request timeout; larger histories need the browser client. Only the documented export object is saved, after account/format validation. The user’s chosen provider may be cloud-backed; JSON is unencrypted and remains after sign-out. Cancellation/failure can leave a partial file, explicitly disclosed and never silently deleted. No app disk payload or permanent URI grant is retained. Automatic registry tests and real provider fixture I/O do not replace manual system-picker/provider/process-death/API26 acceptance or live account export. No live MFA code has been consumed for step-up tests.
- A compatible v3.2.1 HTTPS test server has been supplied; opt-in live password/session-restoration/logout plus read-only room directory/detail/context/history/mutation/ping HTTP checks passed. No live room read/send/presence/membership mutation was performed. That test uses an in-memory vault; real Keystore behavior is tested separately on Android. Native live-server UI, live chat, TalkBack and push-device acceptance remain unverified; no release signing identity was supplied. Release APKs remain unsigned. Firebase project/configuration is unnecessary.
- The maintainer connected the Claude credential and installed the official workflows in PR #5. [PR #3](https://github.com/Thiesi/ChitChat-Mobile/pull/3) records repeated actual reviews, duplicate-trigger consolidation, runtime tool auditing and verified publication. M1 hosted CI initially failed target-version lint and compact-screen scrolling; local fixes pass, and actual current-head hosted verification is recorded in PR #4. See [setup](claude-review-setup.md).
- Native passkey origins and secure browser handoff are absent from v3.2.1. M2a implements recovery-code login with emergency/single-use warnings and contract tests; no live MFA credential has been consumed. Recovery is not passkey parity. Provider-only accounts need B2 for native end-to-end workflows. Guest session detection is fail-safe handling, not implemented guest visitation.
- UnifiedPush is accepted but not implemented. It supplies valid Web Push endpoint/keys for existing server subscriptions; raw Firebase SDK tokens remain incompatible. Prefer an installed distributor, optional embedded FCM fallback, no mandatory publisher relay. Ordinary-DM alerts and final public identity/distribution remain separate unconfirmed decisions. See [push architecture](push-architecture.md).
- The effective installation-name override is not public JSON; native capabilities have no explicit discovery contract. The revision-review participant-notification policy flag disagrees with the documented/trigger-derived notification behavior; B5 requests clarification.
- PHP cookies are session cookies with lifetime zero. Android encrypted restoration uses an explicit bounded client policy, never guaranteed server persistence. Guest credentials remain session-only and are not restored across a cold app start.
- SSE is retention-limited and authorization-filtered; there is no explicit expired-cursor or snapshot/current-watermark response. Foreground reconciliation is required even when the connection resumes successfully.
- M3c3a/b use bounded6×100 raw-row canonical reads, not a server snapshot. Incomplete coverage stays stale with explicit recovery; older nonoverlap keeps a fixed range/New messages action rather than stitching gaps or jumping. No durable event/content cache exists.
- M3c3b wires process/session events into canonical room/directory reconciliation and native presence/inactivity UI. Account/lifecycle scope entry always reconciles. Resume/network recovery never invents human activity; explicit Enter/Stay and acknowledged sends do. Native fixtures do not prove live two-account chat, physical-device, API26 or TalkBack acceptance.
- History has older-ID pagination but no efficient around-message route. Deep links/search results may require many pages and a cancellable loading/unavailable path. Never claim instant navigation or silently substitute unrelated newest messages.
- DM conversations are capped at 100 without pagination. DM read marks all incoming unread messages from the selected peer; precise only-rendered-ID acknowledgment is not available.
- Send/upload endpoints have no idempotency key. Automatic retry after ambiguous network failure can duplicate a message; native UI must preserve an explicit delivery-unknown state.
- DM history/SSE lack complete mutation/file metadata. M4a implements exact-ID mutation/file enrichment for HTTP history/previews; native event/UI consumers remain M4b. A literal `Message deleted.` body is not a deletion flag. Only bulk history/preview/mutation success JSON permits16MiB to support PHP-escaped Unicode/full quotes; excessively large batches fail explicitly. Small/auth/error JSON remains1MiB; no unbounded response buffer.
- Installed UnifiedPush distributors can work without Google Play services. Optional embedded FCM depends on maintenance-sensitive Play Services registration IPC, whose longevity is not guaranteed. OS permission denial, channels, force-stop and vendor background restrictions can delay/prevent alerts. No distributor/fallback end-to-end test has passed; foreground reconciliation remains mandatory.
- The pinned Web Push PHP dependency omits a non-default push endpoint port from the VAPID audience. Use HTTPS443 endpoints until fixed; B4 tracks that defect plus dispatch reliability. B3 tracks shared lifecycle/key/endpoint security. These replace earlier FCM-specific proposals and are not prerequisites for basic HTTPS443 interoperability.
- Persistent local content caching, even encrypted, is not E2EE or a guarantee against a compromised device. Local cache must obey expiry/logout/isolation; server revocation cannot retroactively erase copies a user explicitly exported/shared.

Optional future backend improvements are around-message lookup, snapshot/cursor reset, send idempotency, paginated conversation list and bounded DM read-through ID. These are useful reliability/scale improvements, not fundamental blockers to current browser-feature parity. They are not silently assumed in production code or confused with the required B1-B6 issues.
