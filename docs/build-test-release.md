## Toolchain setup

M3a adds the [native room directory/membership/creation slice](milestones/M3a-room-directory.md). Its opt-in live case additionally GETs the authenticated room list and a visible room's details; provision at least one visible room for the dedicated account. It never joins/leaves/creates rooms, changes presence/reads or posts messages. Fixture/native tests and the remaining M3b/c chat/realtime acceptance are separate gates.

Install Android Studio or Android command-line tools, **JDK17**, Android SDK platform **36** and an API26+ device/emulator. Accept the Android SDK licenses. AGP uses build-tools35.0.0 by default and can install it when licenses allow. Set `JAVA_HOME` and `ANDROID_HOME` to your own installation paths, or use Android Studio's SDK location/local `local.properties`. The wrapper downloads checksum-verified **Gradle8.13**. AGP8.13.2, Kotlin2.3.21 and Compose BOM2026.06.01 are pinned in `gradle/libs.versions.toml`; compile/target SDK36, minimum26. These are a deliberately compatible stable set, not a claim of newest-available versions. Review upgrades together and rerun all gates. Keep `local.properties`, SDK paths and signing keys out of Git.

For the agent validation environment, the JDK, SDK, Gradle cache and emulator were downloaded under ignored `.tooling/` and configured only per shell. They are not checked in and do not exist in a fresh clone. No Firebase project or `google-services.json` is needed. Windows restricted-profile execution can prevent adb finding its user directory; local connected tests used the approved unsandboxed runner, not weakened application security.

## Local checks

For keyboard/device journeys, `testing/NativeTap.kt` supplies one system-injected finger down/up at the clipped target's actual screen position. Use consistent `performNativeTap` routing for native input/modal controls; Compose `performClick` is direct View-level MotionEvent dispatch, not OS routing. The existing `tapNativeInput` still requires focus/display and, with `expectSoftKeyboard=true`, positive IME within the original5seconds. Seven native helper cases and a100-cycle legacy-production-editor/dialog fixture cover this test-only boundary. No tap retry, forced focus/show, extra readiness wait or window workaround is allowed; injection errors remain failures. Default-display instrumentation only. See [scope and actual gates](milestones/system-native-taps.md); isolated passes do not replace full native, device/provider or live acceptance.

Use the same Android user home for **all** app/test APK build invocations. In the agent environment this is ignored `.tooling/android-user-home` (`ANDROID_USER_HOME`, with `ANDROID_AVD_HOME` under its `avd/`); fresh shells must set it again along with JDK/SDK/Gradle paths. Mixing a test APK built with the default user home and an app APK built with the repository-local home can produce different debug certificates. Verify/rebuild both together; never weaken Android's instrumentation signature check or copy/delete signing keys to bypass it. Test-runner launch rejection is not a UI-test result.

CI already disables system animations. For comparable deterministic UI tests, use a **dedicated** emulator/device and disable window, transition and animator scales in Developer options, as [Android's Espresso setup guidance](https://developer.android.com/training/testing/espresso/setup) recommends. With an explicitly selected test serial, the equivalent commands are `adb -s SERIAL shell settings put global window_animation_scale 0`, `transition_animation_scale 0`, and `animator_duration_scale 0` (repeat the full command for each key). Record/restore previous values before separate animated/manual acceptance; do not change another user's device. This is test setup, not an application behavior change. Issue31 remains open for an intermittent animation-enabled suite-only IME failure; report such results separately, preserve failures and keep original tap/focus/IME assertions and timeouts.

From the repository root with JDK/SDK configured:

```powershell
.\gradlew.bat --version
.\gradlew.bat :app:assembleDebug :app:testDebugUnitTest :app:lintDebug :app:assembleRelease
.\gradlew.bat :app:connectedDebugAndroidTest
```

On Linux/macOS use `./gradlew` instead. Connected tests require an online supported device (`adb devices`); skipped tests never count as passed. Debug APK: `app/build/outputs/apk/debug/app-debug.apk`, development identity `io.github.thiesi.chitchat.debug`; install with `adb install -r` and launch normally. M2a contacts the chosen server only after its address is saved, using verified HTTPS. Unit/lint reports are under `app/build/reports/`; connected reports under `app/build/reports/androidTests/connected/debug/`. Release is shrunk but unsigned, not a distributable artifact until separately signed. Public identity/distribution/signing remain unconfirmed.

Ordinary connected journeys do not require a software keyboard on a hardware-keyboard device. To verify the explicit IME-open send precondition on a configured test emulator, enable its software keyboard (`adb shell settings put secure show_ime_with_hard_keyboard 1`) and add `'-Pandroid.testInstrumentationRunnerArguments.expectSoftKeyboard=true'` to the connected-test command (quote the property in PowerShell). CI declares that environment and checks a real positive IME inset before sending; typing into a field alone is not proof that the keyboard appeared. No click/POST retry or enlarged five-second predicate timeout is used. Restore test-device preferences afterward where applicable. Landscape/font-specific runs also accept `expectedOrientation=2` and `expectedFontScale=1.5` runner arguments, asserted per scoped conversation test; a requested rotation alone is not proof.

For dedicated-emulator landscape coverage, first record `adb -s SERIAL shell wm fixed-to-user-rotation`, `wm user-rotation`, and the current `settings get system font_scale`. Some test-host windows request NOSENSOR; a user rotation lock alone then leaves the display in portrait, including after background/resume. Temporarily use `adb -s SERIAL shell wm fixed-to-user-rotation enabled`, `adb -s SERIAL shell wm user-rotation lock 1`, and `adb -s SERIAL shell settings put system font_scale 1.5`. Before starting instrumentation, independently verify `adb -s SERIAL shell cmd activity get-config` reports `land` and retain the per-case `expectedOrientation=2`/`expectedFontScale=1.5` assertions. A requested lock is not evidence of actual configuration. Restore the recorded fixed-rotation policy, user-rotation policy and font scale afterward; never change another user's device or weaken configuration assertions. M4c4c2 preserves its initial orientation-precondition failures separately from corrected device coverage.

## Opt-in live authentication test

Ordinary `testDebugUnitTest` and CI entirely exclude `LiveSessionTest`. There is no hidden external-server test or automatic credential-file read during normal builds. To exercise the existing real password/session contracts explicitly:

1. Provision a dedicated **password-only, non-admin, non-production** test account. This test must not consume a person's MFA recovery codes. Never put production credentials in this repository or chat.
2. Create user-owned `.env.integration` at the repository root with `CHITCHAT_TEST_SERVER` (the test HTTPS origin), `CHITCHAT_TEST_USERNAME`, and `CHITCHAT_TEST_PASSWORD`, one `KEY=value` per line. Matching surrounding single/double quotes are supported; there is no shell expansion/evaluation. All three values must be nonempty. Keep values/whitespace inside a password as intended. Verify `git check-ignore .env.integration`; never stage it.
3. Run `.\gradlew.bat :app:liveSessionTest --console=plain --max-workers=2` (or `./gradlew`). Do not enable HTTP body logging, Gradle debug logging, or print the configuration. The test loads values directly; secrets are not Gradle task inputs or command-line arguments. The task is deliberately non-cacheable and reruns every invocation.
4. Inspect `app/build/reports/tests/liveSessionTest/`. The test signs in, refreshes, recreates the repository, GETs directory/detail plus fresh conversation context/history/mutation metadata/private pings for the first visible room, signs out and attempts reuse of the now-logged-out cookie. Provide at least one visible room whose history that account can access. It sends no message and changes no room read cursor, membership, presence, account or password; the server will record its normal authentication audit entries. Cleanup attempts server logout even after failure. Live send/read acceptance requires separate approval and a dedicated room; merely adding credentials does not authorize those mutations.

This is an actual JVM HTTP/server integration check using transient in-memory credential storage, not an Android Keystore/process-death/UI acceptance claim. Android encryption and forms have separate instrumented tests. Live results must be recorded separately from fixture counts. The supplied test URL and credentials are not baked into the application or public CI.

## Automated coverage and CI

`.github/workflows/android.yml` defines credential-free JDK17 build/unit/lint/release checks and an API36 Google APIs emulator journey job. Gradle setup validates wrapper JARs. Reports and the development APK are uploaded as artifacts. Workflows have read-only repository access and pinned action revisions; review upstream releases/security changes deliberately before updating pins and rerun gates. Public CI never authenticates to a real ChitChat account or embeds Firebase/service/signing secrets. Test-only fakes belong to test source sets. Separate [Claude review setup](claude-review-setup.md) needs a maintainer-supplied Actions secret and is not required to compile the app.

CI's `python3 -B .github/scripts/native_journeys.py` runs the original connected-test command once, preserving its exit status. On failure only, it attempts a15s `ImeTracker`/`TestRunner` capture and writes at most2000 allowlisted scalar/lifecycle records into the existing native-report artifact. It never writes raw logcat or falls back to arbitrary exception/body/window dumps; capture failure does not turn the gate green. Run its credential/device-free checks with `python3 -B -m unittest discover -s .github/scripts -p 'test_*.py'` (`python` on this Windows host). See [scope, recorded failures and verification](milestones/native-ime-diagnostics.md). This is fixture CI diagnostics, not permission to collect private live-conversation logs.

Start an owned local emulator from the stable repository root, not a transient worktree: Windows can keep its launch working directory open after Git unregisters a completed worktree. Preserve reports/APK hashes before normal worktree removal; stop only the verified owned emulator when needed for that owned-directory cleanup. Never reset a shared adb server or alter ACL/OneDrive attributes to force removal.

Cold-boot completion is not window readiness. Before a dedicated-emulator UI gate, inspect its actual focused window and awake/lock state locally (the scalar `mCurrentFocus`/`mFocusedApp`/power fields, not an exported raw private window dump). An unrelated preinstalled-app or System UI ANR can own focus even when `sys.boot_completed=1`. Preserve the first failure and its safe screenshot/metadata, stop an invalid run and correct that specific device fault before a fresh full gate. Record both attempts; never turn an aborted/failed run into a pass, automatically retry tests, force application/IME focus, enlarge assertions or disable critical system packages to hide it. M5a1 records an observed Digital Wellbeing/System UI cold-boot failure and clean owned-emulator recovery without a data wipe.

Lint warnings are fatal except `AndroidGradlePluginVersion`, `GradleDependency` and `NewerVersionAvailable`: these are newer-version suggestions, not code/security findings. They are excluded explicitly in `app/lint.xml` so unrelated online version changes cannot break a pinned build. This is not a general lint baseline or security-warning suppression.

The intentional M1 `targetSdk=36` declaration also has a narrowly scoped `OldTargetApi` exception in `app/lint.xml`: runners with newer SDKs otherwise disagree with the tested local SDK36 installation. API36 meets the [current 2026 Play submission floor](https://developer.android.com/google/play/requirements/target-sdk); [AGP8.13 supports at most36.1](https://developer.android.com/build/releases/agp-8-13-0-release-notes). This is not a production release waiver. Review the complete SDK/AGP/Kotlin set, current target requirements and Android17 local-network/privacy permissions before network/release acceptance. No other code/security lint rule is disabled.

Run focused tests per change and all required milestone checks before merge. Capture exact command/result/count and environment. Mock contract tests are not a real server integration; compilation is not a UX review. Do not add trivial tests merely mirroring layout constants.

## Manual/device acceptance

Use two accounts and representative staff/guest roles on a compatible non-production server. Exercise real room/DM/history/reconnect/block/edit/files/search/report/account/admin flows, password and configured MFA/provider paths, privacy disclosures and forced invalidation. Device review covers portrait/landscape, compact/expanded windows, font scaling, TalkBack, contrast, keyboard/focus, slow/intermittent network and app process death. Push acceptance needs two distributors and the optional embedded fallback as defined in [setup](firebase-setup.md#end-to-end-manual-test-once-implemented).

## Release gate

Before calling a build production-ready: all applicable parity rows completed or genuine blockers explicitly disclosed, full required CI green, release/shrinker build and install passed, real core-chat acceptance recorded, backend-dependent gaps and notification limitations clear. Produce signed APK and optionally AAB with maintainer-controlled keys after public identity/distribution is confirmed; never invent an approved production signing identity. Document actual SDK requirements, backend compatibility, application ID and privacy/data safety disclosures. Public alpha cannot claim complete native MFA or push while their relevant acceptance is outstanding.

When publication is authorized, verify the remote commit/tag/release, asset hash/signature and a freshly downloaded installation artifact. A local build or merged PR is not published-release verification. No release or Play deployment has been performed in discovery.
