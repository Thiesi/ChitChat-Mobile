# ChitChat Android engineering

- This repository owns the native Kotlin/Jetpack Compose client only. Never edit, commit, fetch into, or otherwise mutate the sibling `Thiesi/ChitChat` checkout. Backend issues are permitted; backend patches are not.
- Read [discovery](docs/discovery.md), [compatibility](docs/backend-compatibility.md), [parity](docs/feature-parity.md), [push decision](docs/push-architecture.md), and [milestones](docs/implementation-plan.md) before implementation. M1/M2 supply native foundation/auth/step-up/export; M3a/b/c supply directory, canonical realtime rooms and deliberate presence. M4a/b1/b2 supply DM protocol/state/native screens. Milestone documents record exact verification boundaries. M4c typing/ignore/notification center, push and live chat acceptance remain pending. Public identity/distribution and ordinary-DM alerts remain separate decisions.
- For structural codebase exploration use the installed `codebase-memory` skill. Check index freshness and coverage; read source for missing, stale, or unusable coverage. Do not reindex the backend as part of this task: that writes to its checkout.
- Fetch the Android remote and compare the base before branching. Preserve unrelated work. Use focused commits and reviewable milestone PRs; never merge failing checks or conflicts.
- Standing delivery order after each buildable milestone: commit/push, open a PR to trigger Claude review, wait for completion, triage realistic product impact and fix worthwhile findings, then comment tagging `@claude` for another review. Repeat until no worthwhile fixable findings remain; merge only after required checks pass and conflicts are resolved. Remove only verified obsolete branches/worktrees, preserving others' work.
- Continue autonomously into the next independently buildable milestone after delivery; do not wait for routine milestone confirmation. Pause only for a genuine blocker, missing authority/configuration needed for the affected work, or a consequential product/security decision that cannot safely be resolved from existing instructions. Report the problem and continue unrelated authorized work where possible; this does not waive verification/review gates or broaden live-server mutation permissions.
- Claude Actions setup is documented in `docs/claude-review-setup.md`. With its scoped workflow token, Claude-generated reviews appear as `github-actions[bot]`. Missing credentials, a skipped job, silence, or a review of an older head never satisfies the review gate.
- M1 uses JDK 17, Gradle 8.13, AGP 8.13.2, Kotlin 2.3.21, compile/target API 36 and minimum API 26. Use the checked-in wrapper and catalog; run debug/release build, unit tests, lint and connected tests. Review dependency upgrades as a compatible set. Only newer-version hints and the explicit M1 target36 declaration are excepted in lint; reassess SDK/AGP/current target and Android17 network/privacy permissions before production.
- Existing contracts use PHP session cookies, `X-CSRF-Token`, foreground SSE, and Web Push `{endpoint,p256dh,auth}` subscriptions. UnifiedPush uses that existing push contract, installation VAPID key and `aes128gcm` worker. Prefer an installed distributor; an embedded FCM distributor is optional. No mandatory publisher relay, Firebase project, `google-services.json`, or sender credentials. Superseded FCM-token API drafts are not existing APIs; neither are proposed native-auth routes.
- Use Compose, ViewModels, coroutines/Flow, typed DTOs, and repositories. Keep UI out of networking and authorization decisions on the server. Extract abstractions only for concrete reuse or testing.
- M2a uses compatible OkHttp5.4 and serialization1.10 with Kotlin2.3/API36. OkHttp5.5 requires API37; serialization1.12 requires Kotlin2.4. Upgrade these as a verified toolchain, not by editing a single version. Typed OkHttp calls currently suffice; do not duplicate the HTTP/session layer for later features.
- M2b1 registration/restoration reuse that session layer; see `docs/milestones/M2b-registration-restoration.md`. Register succeeds with201; restore202 is still pending. Proofs are session/attempt-bound, single-use, cancellable and non-persistent. Never guess server fill timing, silently retry a POST, or keep password/birth-date/picker state in saved-instance bundles. Live disposable-account mutations need explicit approval.
- M2b2 reuses generation-bound `SessionAccess`, the typed session transport, `withStepUp` (only403/step_up_required, one retry) and the generic `StepUpDialog`. Passwordless/MFA policy is discovered, never guessed. Recovery is explicit emergency consent, consumed even if the later action fails; propagate confirmed remaining counts. No automatic verification/recovery POST replay. Cancel on genuine background/navigation/logout, not configuration recreation; retain the requested operation in the Activity ViewModel and wait for navigation restoration. Bind document-picker callbacks to their original generation too.
- Exports choose a new SAF document before HTTP. Keep payloads out of UI/saved state/logs/app disk and do not retain URI grants. The common transport has a bounded16MiB export response and120-second timeout. Only bounded room/DM history, DM previews and mutation batches also allow16MiB (PHP Unicode escaping/full quotes); these keep25-second timeouts. Auth/other small JSON and all error responses retain1MiB. Validate account/format before chunked, cancellation-aware provider writes. The chosen file is an explicit unencrypted export, survives logout, and may be partial after failure; never silently delete it. Document-picker fakes and real provider fixtures are not manual cloud/provider/live-account acceptance.
- `.env.integration` is user-owned and ignored. Never display its contents or put credentials in commands, issues, commits, reports or logs. Only the explicitly invoked `:app:liveSessionTest` consumes its values. Normal unit tests exclude live tests entirely, rather than silently skipping them.
- `SessionRepository` serializes local generation/state/vault changes, never network waits. Each `SessionHttp` owns its dispatcher, pool and origin-bound retireable jar. Follow redirects/retry-on-failure stay disabled; requests and cookie import/export never leave the chosen HTTPS origin/API paths. Secrets have no generated data-class string representation. Never publish a user from encrypted storage before server bootstrap.
- Scope secrets, content, cursors, requests, jobs, and notifications by server, account, and local session generation. A stale callback must never repopulate a signed-out account. Never log credentials, cookies, CSRF, tokens, search terms, or message bodies.
- Shared bootstrap cancellation must release busy in runtime-fenced non-cancellable local cleanup, clear CSRF and require ordinary revalidation; rethrow cancellation. Never leave a cancelled room/DM policy refresh permanently blocking the whole session, or let its cleanup mutate a replacement/sign-out runtime. See `docs/milestones/session-bootstrap-cancellation.md`.
- M3a room directory/membership/creation reuses `RoomOperations`/`SessionRoomRepository` and the same `SessionAccess`; see `docs/milestones/M3a-room-directory.md`. Detail/join/create omit list unread fields. Owners cannot leave; invitations alone do not authorize private history. Failed/uncertain writes require explicit GET reconciliation, never POST replay. Room drafts/metadata stay in generation-scoped VM memory, not saved state or disk.
- M3b uses `ConversationOperations`/`SessionConversationRepository`, the same transport/capability and fresh bootstrap ignore/mute/display policy. See `docs/milestones/M3b-room-conversation.md` and its protocol prerequisite. History is ascending/exclusive-before, enriched with exact-ID mutation metadata; retain raw pagination boundaries and deleted-message reactions. Read can return0/already-advanced cursors; acknowledge only an actually visible foreground latest window. Keep private pings separate. No text-based send dedupe or POST replay: unknown delivery needs GET reconciliation then explicit duplicate-risk consent. Bound memory to500 messages/100 pings, preserve anchors, clear account-scoped state, and never save content/drafts into bundles. SSE/presence remain M3c; manual refresh is explicit.
- Preserve DM non-E2EE/retention/inspection disclosures, ignore versus block semantics, guest restrictions, step-up, mute/rank rules, and the difference between membership and active presence.
- No automatic retries of ambiguous message/upload POSTs: the existing API has no send idempotency key. SSE is an invalidation/replay transport, not complete authoritative storage. Reconcile on foreground entry.
- M3c2/3 connect process-owned foreground events, native announcements, canonical room/directory invalidations and presence UI. See `docs/milestones/M3c3b-room-realtime.md`. Scope collectors to account/generation, re-read on entry, coalesce invalidations behind writes without POST cancellation/replay, and preserve visible-read/send-unknown rules. An open stream is not proof of current history. Passive resume/network recovery must not synthesize room reentry/activity; null cleanup is only for a possibly acquired lease.
- M4a's `DirectOperations`/`SessionDirectRepository` reuse `refreshedAccess`, the same session transport/capability and ephemeral typed privacy policy. See `docs/milestones/M4a-direct-protocol.md`. DM mentions/quotes differ from room schemas; enrich history/previews with exact-ID mutations/files and preserve raw pagination. Confirmed sends return IDs before any fallible refresh. Whole-peer read has no through-ID: refetch and preserve separate local unseen attention. Never infer another user's block, treat ignore as block, or invent privacy defaults.
- M4b1 adds canonical DM windows and inbox/thread VM state, not screens; see `docs/milestones/M4b1-direct-state.md`. Retain fixed upper bounds even after all rows vanish. Fence every await, queue/coalesce invalidations behind writes, and never grant uncertain-send consent through automatic entry/sync. Whole-peer read needs actual viewport proof and post-read reconciliation/local attention, not a fabricated server cursor.100 memory drafts never silently evict; expose explicit discard/capacity UX in M4b2. Neither saved state nor logs may contain their content.
- M4b2 consumes those states in native inbox/thread screens with strict route-scope checks before composition and on selection. See `docs/milestones/M4b2-native-direct-messages.md`. Use actual RESUMED/window-focus/unobscured/live-edge/newest-bottom visibility for reads, not STARTED synchronization or a full-row-fit requirement that starves tall messages. Keep the composer and details/errors reachable with IME/large fonts; no automatic resend/read retry or extra background service. Test fakes stay in `androidTest`. Typing/ignore management/notification center remain M4c; attachment and author actions M5; push M6.
- Every milestone must compile, pass relevant tests, update parity/status docs and existing in-app feature-availability disclosures, and commit. Report exactly what ran. Do not equate mocked tests, compilation, or foreground chat with device/FCM end-to-end success.
- Signing material and final public application identity must be confirmed by the maintainer. No invented identifiers, private keys, service accounts, or production URLs. Optional embedded FCM uses UnifiedPush's Web Push registration path, not the Firebase SDK; verify its Play Services IPC compatibility on devices before release. Keep test fakes out of production source sets.
